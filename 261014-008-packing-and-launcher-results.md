# Packing, emit, --style and the Python launcher: results

## What pure ASCII means for your system

Short answer: nothing visible changes. "Pure ASCII" describes only the text of the script files themselves, not your data. Your tasks.toml, the notes in it, the stylesheet that `emit style` prints, and the HTML pages that `preview` writes are all still UTF-8 and still contain every special character they had, such as the bullets and dashes in notes or titles. What changed is how the script file spells those characters internally: where almanac.tcl needs a dash or a square bullet in a string it now writes a short code (`—`, `■`), and where the packed file stores the CSS and JavaScript it writes each special character as a token like `@@U+25A0@@` that is turned back into the real character when the asset is used. The reason is Tcl 8.6, which reads a script file in whatever encoding the terminal's locale says (often Latin-1), so a raw bullet inside a script came out as garbage in the preview there; Tcl 9.0.4 reads UTF-8 and never had the problem. A file that contains only plain ASCII is read the same way by every Tcl in every locale, so one packed file can run under 9.0.4 and 8.6.14 with identical results. The cost is that the packed file is not directly readable where those characters occur; the sources in skin/ stay normal UTF-8, `emit` gives you the real files, and `pack-almanac.tcl --unpack DIR` cuts a packed file back into the originals.

## What was built

`task-writing-kit-v002/pack-almanac.tcl` (Tcl) builds `task-writing-kit-v002/dist/almanac.tcl` (1.5 MB, 26,102 lines, zero non-ASCII bytes) from the editable `tools/scripts/almanac.tcl`. The loose script stays the one you edit; it gained `emit`, `setup`, `preview --style`, an asset accessor that falls back to the skin folder when the packed variables are absent, and `catch {encoding system utf-8}` at the top. In the packed file, cli.tcl and the tosu tama.tcl are inlined in place of the deps block, then the four text assets and the 13 fonts, each fenced with MODULE, ASSET or FONTS lines so a reader can reconstruct the standalone pieces by eye or with `--unpack`. The build checks that every asset is safe as a braced literal (balanced braces, no backslash before a newline or brace, no trailing backslash, no carriage returns), that the dev script is pure ASCII, that there are exactly 13 fonts and that every `url("fonts/web/...")` in artifacts.css has one, then writes the file and self-tests it. The build is deterministic: a second build is byte-identical, and `--check` reports whether dist is current.

## Verification against section 5 of the plan

1. emit versus sources: pass under both Tcl 9.0.4 and a real tclsh 8.6.14. `emit style` equals artifacts.css and `emit template` equals sight-index.html byte for byte; `emit fonts` produced 13 of 13 fonts byte-identical to the originals; board.css and board.js decode back to their sources (checked by the build itself on every run, and by an `--unpack` round trip).
2. Old versus new preview: pass. The loose script (reading skin files), the packed script (embedded assets) and the packed script under 8.6.14 produce identical HTML for the same payload once the generation timestamp is masked, including the fonts. Under 8.6.14 the old script's bullet bug is gone as well.
3. `preview --style`: pass. A full custom theme gave a page with the same 284 cards and a changed text color; a theme that redefines only two variables loads but falls back to a default font, and the script warns that it lacks 82 variables the standard theme defines, so the warning is useful. I replaced the original "structural selectors present" test with a headless Chromium render check as agreed. The warning is based on the standard theme, not on board.css, because the fonts and body rules live in artifacts.css.
4. Verb regression: pass. ls, `--toml ls`, today, ready, blockers, validate, add, set, done, change, apply and show give identical output, exit code and resulting file across the pre-packing script, the loose script, the packed script on 9.0.4 and the packed script on 8.6.14 (ids, stamps and change times masked where they are random). doctor exits the same way and prints the same number of lines in all three; it checks a /workspace environment that does not exist here, so only that it does not crash was compared.
5. Launcher parity: pass on tkinter's Tcl 9.0.4. Every verb above, `emit style`, `-h` and the preview produce the same output, exit code and files through `./almanac` as through `tclsh`. This is not tested on tkinter's Tcl 8.6.14 because no Python available here ships one (the system Python has no tkinter, and every standalone build I could install embeds 9.0.4). To check it on your machine, run `./almanac --file snapshot/tasks.toml validate` and `./almanac --file snapshot/tasks.toml preview /tmp/p.html` and compare with `tclsh almanac.tcl` on the same arguments.
6. `almanac setup`: pass. In a temp directory it wrote an executable launcher beside the script, printed `alias almanac='/absolute/path/almanac'`, ran `preview` end to end, baked in an absolute path when given another directory, and refused to overwrite a file that is not a launcher. It does not touch shell startup files.
7. Exit interception: pass. `validate` on a bad file, a missing file, an unknown id, an unknown verb, and no arguments return exit codes 1, 1, 1, 1 and 2, the same as tclsh, with identical stdout and stderr and no Python traceback; piped output arrives complete.

## Choices I made that you may want to change

`emit` refuses to overwrite an existing output file unless `--force` is given, in line with `apply`. `emit fonts` keeps the original layout below the target directory (fonts/web/X.woff2 goes to DIR/web/X.woff2), so with the default ./fonts a stylesheet beside it still resolves its font urls. The packed file still carries the original `#!/workspace/system/deps/tcl` shebang line from the live script; it only matters if you execute the file directly. In the launcher, the first `exit` code wins even if Tcl code were to swallow the exit with a catch; I did not find any current code path that does.
