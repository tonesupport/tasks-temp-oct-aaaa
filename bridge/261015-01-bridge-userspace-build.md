# Bridge Tcl userspace: what was built, and what needs your call

## Read these two things first

**The current build cannot boot a userspace this size, and an oversize boot kills the interpreter for good.** The adapter boots the shell with `ip.Eval(window.__shTcl)`, and wacl copies that whole string onto the WebAssembly stack, which holds about 64 KB. I measured it: a 64 KB string evaluates, a 70 KB string dies with `RuntimeError: memory access out of bounds`. The adapter does print `shell profile failed: RuntimeError...`, but I also checked what happens next, and nothing recovers: every later command, even `expr {1+1}`, raises an error whose message is garbage, because the shared interpreter is dead for every window until the page is reloaded. The readable `sh.tcl` is 134 KB (44 percent of it is help text), so embedding it as it stands would brick the shell at boot. The same limit applies to anything pasted at the prompt, since each line goes through the same `Eval`. I did not change the runtime or the build. Instead I did two things. First, `pack-sh.py` compresses `sh.tcl` (raw deflate, base64) into `sh-boot.tcl`, a 56 KB plain-Tcl stub that inflates and evaluates it; embed `sh-boot.tcl` where the build embeds `sh.tcl` today and nothing else has to change. I booted exactly that file in the real page in Chromium and it works. Second, the proper fix is a build or adapter change of about three lines, which I recommend but did not make: have the adapter write the profile into the virtual file system and source it from there, so the size limit disappears and you can embed the readable file. In `makeWaclAdapter`, replace `ip.Eval(window.__shTcl)` with `ip.Module.FS.writeFile('/usr/lib/sh.tcl', window.__shTcl); ip.Eval('source /usr/lib/sh.tcl');`. The test suite already exercises both routes (the readable file sourced from the file system, and the packed file through the real adapter). `pack-sh.py` refuses to write a stub over 62,000 bytes, and the suite enforces the same budget, so you will be told before help text outgrows it.

**Two inputs were not in the upload.** `nushell-for-tcl.md` and the existing `test-shell-memfs.js` never arrived, so I worked from the briefing's description of the structured layer and wrote the test file from scratch following the architecture document (boot the real runtime, extract `makeWaclAdapter` from the HTML, test the profile, the adapter, the old shell's absence). If your original test has checks I do not replicate, merge them in. Please check my structured-layer names and argument orders against the nushell document, especially the one deviation I flag below about `each`.

## What is in the folder

`sh.tcl` is the userspace: 90 commands and 16 guide topics, written as one readable file in six marked sections (core and help, places, text, values, fluidity, topics). `sh-boot.tcl` is the generated packed form to embed today; never edit it. `pack-sh.py` makes it. `test-shell-memfs.js` is the suite: 613 checks, all passing, covering for every command the happy path, empty input, missing keys or arguments, and the exact first line of every error message. Run it with `node test-shell-memfs.js [path/to/bridge-wacl.html]`; it takes the runtime and adapter from the HTML and reads `sh.tcl` from beside itself, so no rebuild is needed to test a change. I left `bridge-wacl.html` out of version control because it is generated and 6 MB. I did not touch the HTML or the build script.

Beyond the Node suite I drove the real page: I patched an in-memory copy of the HTML to embed `sh-boot.tcl`, opened it in Chromium, and typed a session into the actual prompt. The profile booted without page errors, results and errors rendered, and `help` printed. I did not test other browsers.

## How it works

Everything follows from three shapes. **Text** is a string of lines with no trailing newline (a newline is a separator, not a terminator); `cat` gives it and `grep`, `sort`, `uniq`, `sed` and the other Plan 9 style tools take and give it. **Lists** are Tcl lists, and **rows** are lists of dicts. Text tools may split on newlines safely because a line is defined as what lies between newlines; nothing ever re-splits a list. `lines`, `unlines`, `parse`, `pluck`, `table`, `from-csv` and `from-json` are the deliberate crossings. I think this two-world split is the honest reading of "Plan 9 first, nushell third", but it is the biggest structural choice in the build, so it is listed under decisions below.

Every command takes the thing it works on as its first argument, uses only single-letter flags that come after the input (`-la` means `-l -a`, `--` ends flags), and fails with `command: what went wrong` on the first line. Anything that returns a list returns it one item per line. That is still a perfectly good Tcl list, because newline separates list items, but it reads properly at the prompt instead of as one run-on line; I verified this through the real adapter. Names with spaces appear in braces, which is honest. Because a one-per-line list and the same list on one line compare unequal under `eq`, there is a small `same` command, and the `values` guide explains the trap.

Three comforts are worth knowing. File commands expand wildcards themselves, and a pattern that matches nothing stays literal so the error names it (the rc rule). Names beginning with `/` count from the shell's top, so the prompt's `/docs` can be typed as `/docs`, with fallback to the real path for things like `/usr/lib`; bare `cd` and `cd -` work, and the shell starts in its own top instead of the system root. And any file called `NAME.tcl` in `/bin` (that is `/home/shell/bin`), or any path with a slash, runs when you type its name, with `$argv` and `$argc`, in a throwaway scope. That is the answer to "Tcl programs in the VFS where that reads better" and to `./foo` not working. Unknown commands now add a one-line note: a pointer to `help` and `apropos`, or for Unix words like `find`, `man`, `ps` or `awk` what to use here instead.

## The command set and why

Places and things: `ls`, `ll`, `files` (the same listing as rows you can filter), `cat`, `save` (writes text to a file; `-a` appends), `tee`, `mkdir`, `touch`, `rm`, `cp`, `mv`, `cd`, `exists`, `isdir`, `isfile`, `basename`, `dirname`, `cleanname`, `walk` (torgo's tool, recursive, `-f` and `-d` filters), `du`, `date`, `digest`, `hash`, `xd`, `seq`, `calc`, `echo`, `expand`. `save` is what redirection is in other shells, and the `redirection` guide teaches it that way. `rm` refuses to touch `/`, `/home`, the shell's own top and anything under `/usr`, because removing those breaks Tcl itself for every window. `cat` refuses binary data and points at `xd`. `cp` and `mv` overwrite by default and need no `-r` (Tcl copies places whole); `-n` skips existing destinations. `date` is a hand-written UTC formatter because `clock format` does not work in this build; `clock seconds` does.

Text: `lines`, `unlines`, `grep`, `search` (grep over a list of files, which is what makes `search [walk -f] TODO` work), `head`, `tail`, `wc`, `nl`, `fields` (the useful corner of cut and awk), `extract` (torgo's structural-regexp idea: pull the matching pieces out), `fmt`, `tr`, `sort`, `uniq`, `diff`, `sed`. `sort` and `uniq` carry torgo's regexp selections: `-k` and `-x` take a pattern and act on the first group it captures, or the whole match. `uniq -c` counts uniques and duplicates alike as in Plan 9, and `-a` extends it past adjacent repeats, which torgo's duplicate-file example needs. `sed` is a deliberate subset: `s`, `d`, `p`, `q`, `y`, with line, last-line, pattern and range addresses and negation, using Tcl regular expressions. `hash` takes a list of names and gives `sum  name` lines with the algorithm as a plain word, so the torgo pipeline reads `uniq [sort [hash [walk -f]]] -d -x {^\S+}`; the digests (md5, sha1, sha256, crc32) are pure Tcl, checked against the standard test vectors including multi-block and padding-boundary inputs.

Lists and rows: `each`, `keep`, `reduce` (accumulator first, scripts see `$acc` then `$it`), `any`, `all`, `first`, `last`, `skip`, `flatten`, `compact`, `distinct`, `enumerate`, `zip`, `chunk`, `tally`, `sum`, `avg`, `min`, `max`, `sort-on`, `where`, `select`, `reject`, `pluck`, `set-col`, `rename-col`, `sort-by`, `group-by`, `uniq-by`, `columns`, `table`, `parse`, `from-json`, `to-json`, `from-csv`, `to-csv`. There is no `par-each`. Row scripts see the row's columns as variables and also your own variables (so `where $rows {$age > $min}` works), without leaking the columns into your scope or clobbering a variable of yours with the same name; a missing column is an error naming the row and the column, and `pluck` takes a default as the escape hatch. Names that would shadow Tcl built-ins were avoided on purpose: `rename-col` instead of `rename`, `set-col` instead of `update`, no `join`, no `append`. Commands the nushell vocabulary would have added but Tcl already has (`lmap`, `llength`, `lrange`, `lreverse`, `dict merge`, `lsort -unique` and so on) are not wrapped; the `lists` guide maps them.

Fluidity: `|>`, `~` (rc's match: answers 1 or 0 instead of failing), `^` (rc's distribution: a single item glues to every item, equal-length lists glue pairwise, anything else is an error), `same`, `whatis` (shows any proc's source in re-executable form, so every command here can be read and copied), `which`, `alias`, `unalias`, `help`, `apropos`.

Deliberately not built: anything needing processes, network, timers, threads or `clock format` (flagged, not faked); `par-each`; `comm`, `cmp`, `ln`, `chmod`, `cal`, `units`, `bc`, `tar` and the zip family, `enc`/`dec` (use `binary encode`), `loop`, `no` and the network tools. Of torgo's tools I took walk, hash, uniq, sort, wc, tr, tee, seq and the structural-selection idea (as `extract`, `-k`, `-x`); the rest are stubs, redundant with Tcl, or impossible here.

## Decisions for you

**The `|>` threader earns its place, narrowly.** I wrote the same five-stage query three ways (it is in `help pipes`): nested brackets, variable threading, and `|>`. Threading is the clearest when you want to look at intermediate results; nesting reads inside-out and is fine to about three levels; `|>` has no temporary names and reads in pipeline order, at the cost of a second level of braces per step and error traces that mention the threader. It is six lines, it sees your variables, and the tests prove the three forms agree. I kept all three and documented threading and `|>` as equals. If you would rather present only the two honest-Tcl forms, deleting `|>` is a one-block change.

**Help stays baked in, co-located with each proc.** Each `::sh::doc` sits directly under the code it describes, so editing a command and its manual is one move and a test fails if any global proc lacks an entry or any entry lacks a part. At 90 commands the docs and guides are 44 percent of the file and `help` is instant. The reason to split them into VFS files is the boot limit, not taste, and that disappears with the adapter change above, at which point separate files would also need the build to ship them. I would not split before then.

**Wildcards: literal on no match (the rc rule), applied everywhere.** Every file-reading command goes through one function, so it is consistent, documented under `help wildcards`, and the error names your pattern.

**`parse` stays small.** `{name}` captures only, with any run of blanks matching any run of blanks and everything else literal, plus `-x pattern name...` as the escape hatch to a full regular expression. A richer template language would be a second thing to learn next to regexps that people need anyway.

Deviations from the briefing that I would like you to confirm, because each is a one-line flip:

- `each` and `keep` take the list first and the item variable second, `each $nums x {expr {$x * 2}}`, whereas the briefing's prose example writes `each x $nums {...}` (variable first). The briefing's own rule is input first, and that is what makes nesting and `|>` work, so I followed the rule and not the example. The same goes for `sort-on`, and its direction flag is `-r` (single-letter flags everywhere) instead of `-decreasing`.
- Two shapes (text tools versus list tools), as explained above.
- `hash` returns text lines, not rows, so it chains into `sort` and `uniq`; `parse` lifts text to rows when you want them.
- `sort-by` takes one column. My first version took several and applied `-n` to all of them, which sorted a text column numerically; chaining two stable sorts (minor key first) is clearer and the doc says so.
- `from-json` and `to-json` lose type: Tcl values are untyped, so numbers that look like numbers are written as numbers, `true`, `false` and `null` pass through as words, and nested values inside a row are written as strings. This is documented in the command's help.
- The `unknown` handler is replaced (the original is kept and still handles autoloading, and `package require json` is tested). That is a shell-wide hook, so it is the change I would most want a second pair of eyes on.

## Flagged, not done

The 64 KB boot limit above. The `?` help panel's command list is rewritten by the build script, which I do not have; it still shows the old short command list until updated, and `help` is now the authoritative list. Errors print the whole `errorInfo`, so a one-line message is followed by a few lines of internal trace (`while executing "::sh::slurp cat $f"`); the first line is always the useful one, and having the adapter print only the first line of the error for these (with the rest available on request) would make errors much calmer for newcomers. `puts` and `echo` output arrives with a trailing carriage return from wacl's terminal layer; this predates my work and I made the tests tolerate it. `clear` is still adapter magic and cannot be used inside a line. Runaway loops still freeze the page, and `after` with a script and `vwait` still hang; the `limits` guide says so plainly. Everything is still lost on reload, and `cd ..` at the shell's top walks out into `/home`. The profile re-runs for each window and is safe to repeat (the `cd` rename is now guarded; the original would have failed on a second window), but redefinitions you made are overwritten.

## Smaller limits you may meet

`diff` builds a table in memory proportional to the product of the two lengths, so it suits a few thousand lines, not a hundred thousand. `sha1` and `sha256` take about half a second per 100 KB in Tcl; `crc32` is native. `sed` has no `a`, `i`, `c` or hold-space commands. `ls` shows names with spaces in braces. Profile boot takes about 15 ms.

## Guides

`help` lists everything by group with one-line summaries. `help <command>` prints NAME, SYNOPSIS, DESCRIPTION and EXAMPLE. The topics are `start`, `values`, `pipes`, `redirection`, `wildcards`, `regexp`, `errors`, `quoting`, `lists`, `tables`, `scripts`, `shell`, `tcl`, `tcllib`, `vfs` and `limits`. They assume no command-line experience: pipes are explained as results flowing from one step to the next, redirection as sending a result to a file instead of the screen, and nothing relies on symbols the reader has not been taught. A test checks that no help line exceeds 82 columns so pages fit a narrow pane, and another that every example starts with a command that exists.
